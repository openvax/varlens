Varlens Documentation

varlens

A collection of Python tools for working with genomic variants and next-generation sequencing reads. Not particularly fast for large datasets. The emphasis is on extracting what you need from BAMs and VCFs into a CSV file for further analysis.

Built on varcode and pysam.

varlens-variants

Combine, annotate, and filter variants from VCF or CSV files. Available annotations include genes, variant effects, surrounding sequence context, counts of supporting reads from specified BAM files, and MHC I binding affinity prediction of mutant peptides.

varlens-reads

Display, filter, and copy reads from a SAM/BAM file. Partial replacement for samtools view.

varlens-allele-support

Count reads supporting each allele at specified sites in BAM files.

Installation

Varlens 1.0 requires Python 3.11 or newer, pandas 2.3.3 or 3, and MHCTools 4.1.1 or newer (below 5). The package uses the current Topiary 5 prediction API.

To install from PyPI:

pip install varlens

Or from a git checkout:

pip install .

The examples below use test data from the tests/data directory of a git checkout.

varlens-variants

Given variants from one or more VCF or CSV files, apply filters, add additional columns, and output to CSV.

Currently we can only output to CSV, not VCF.

A number of useful annotations can be added for each variant by specifying options of the form ‘–include-XXX’, e.g. ‘–include-gene’. See detailed help (run with -h).

varlens-allele-support

Given one or more BAMs and some genomic sites to consider, write a csv file giving counts of reads supporting each allele at each site for each BAM.

The genomic sites to consider may be specified by locus (–locus option), or via one or more VCF files.

The positions outputted by this command are in interbase coordinates, i.e. starting at 0, inclusive on first index, exclusive on second (as opposed to the one-based inclusive coordinates used in VCF files).

Insertions use an empty interval at the insertion boundary. For example, VCF 1:100 A>AT becomes interbase_start=100, interbase_end=100 with ref="" and alt="T". The pileup reads the base immediately to the left and counts only the inserted sequence. Version 1.0 corrects the older single-base insertion intervals; CSV input still accepts that older encoding.

Examples

varlens-allele-support \
    --reads tests/data/CELSR1/bams/bam_1.bam \
    --locus 22:46931061 22:46931063

source,contig,interbase_start,interbase_end,allele,count
bam_1.bam,22,46931060,46931061,,1
bam_1.bam,22,46931060,46931061,G,329
bam_1.bam,22,46931062,46931063,A,327
bam_1.bam,22,46931062,46931063,AC,1
bam_1.bam,22,46931062,46931063,AG,2

Structural variants and empty inputs

varlens-variants loads symbolic SV alleles and paired/single breakends from VCF using Varcode. A mixed SNV/SV file retains both kinds of event. A malformed structural allele that Varcode cannot parse causes an error before output is written. Empty or all-filtered sources produce a header-only CSV, including when --chunk-rows is used. By default, non-PASS calls are excluded; use --include-failing-variants to include them. VCF . and * ALT placeholders are not independent variant calls. --max-variants-per-source explicitly limits the number of loaded alleles.

Structural rows add two JSON-valued CSV columns:

  • structural_variant: the varlens.structural_variant.v1 envelope and Varcode constructor fields, including type, original alleles, affected span, partner breakpoint, orientation, uncertainty, assembly and INFO data. Genome objects are represented by their canonical assembly name.

  • vcf_records: source paths and retained Varcode VCF metadata, including record ID, filter, INFO and sample fields, plus the original VCF line. Every retained record is kept when identical events are merged, within or across sources.

These columns are retained without --include-metadata and are required for a structural CSV round trip. Do not edit the displayed locus/alleles independently of the typed payload. Custom --columns output can deliberately omit fields, but then cannot necessarily be reloaded. Ordinary variant CSVs retain their existing schema.

For SVs, --variant-locus selects known breakpoint bases, including a remote mate, rather than every base in a deleted/duplicated interval. Confidence intervals are preserved but do not widen this filter. Raw contig spellings are retained in the payload; displayed contigs follow Varcode normalization.

SV export, reload, REF/ALT filtering and breakpoint filtering are supported. Gene/effect/context annotations, the best-affinity variant summary, and single-interval read evidence currently reject SV rows with an actionable diagnostic. Likewise, varlens-reads --variants and varlens-allele-support --variants reject structural events. Explicit --locus read export remains available: those alignments are raw observations, not counts of molecules supporting a junction.

varlens-fusions

Install the optional Isovar adapter and reconstruct supplied fusion RNA:

pip install 'varlens[fusion]'
varlens-fusions fusion.json.gz --out reconstruction.json

Optionally predict junction-overlapping peptides with Topiary and mhctools:

varlens-fusions fusion.json.gz --hla 'HLA-A*02:01' 'HLA-B*07:02' \
    --peptide-lengths 8 9 10 11 --out predictions.json

NetMHCpan and its model data must be installed for the second command. The reconstruction-only command does not invoke it. Multiple JSON/JSON.gz input files can be supplied, and --out also accepts JSON.gz; omitted output goes to stdout. A failed input or prediction prevents writing a partial report.

Each input is an Isovar supplied-fusion input: a JSON object with fusion, references and reads (plus optional reference_names). fusion supplies event identity, assembly, oriented donor/acceptor breakpoints, RNA sequence, mapped blocks, half-open junction coordinates and provenance with a sample ID. References supply annotated transcript sequence/mapping and CDS coordinates; reads supply observed RNA sequence/mapping and sample/library/read/ fragment identity. Isovar validates these fields and transfers frames only from compatible annotated donors. The note and original_records fields in the Sid fixture audit envelopes are retained in the report, but are not counted as additional RNA evidence. Unknown fields are rejected.

The output varlens.fusions.v1 report contains an events list. Each varlens.fusion.v1 event retains the entire input, the unmodified isovar.fusion_rna.v3 reconstruction, software versions, Topiary fragments, and full peptide prediction rows. prediction_status distinguishes not_requested, no_coding_products and completed; a completed run may have no target-overlapping predictions.

Unresolved and insufficient-support outcomes keep their reasons and measured evidence. Ambiguous or partial-CDS coding hypotheses remain separate fragments with explicit status on every prediction; Varlens does not choose an isoform. Junction read/fragment counts retain their supplied-observation scope. Unknown reference counts, protein-observation evidence, UMI/cell counts and comparator sequences are not filled with zero or inferred from alignment counts. Junction overlap is not a claim of proteome-wide novelty or tumor specificity. This command does not discover fusions, assemble arbitrary BAMs, translate structural VCFs, or establish whole-sample expression from selected reads.

Python callers can use the same workflow:

from varlens.fusions import analyze_fusion
result = analyze_fusion(payload, alleles=["HLA-A*02:01"])

analyze_fusion(payload) performs reconstruction only. A configured topiary.TopiaryPredictor can be passed as predictor= instead of alleles. varlens.mhc_binding.fragment_predictions also accepts existing topiary.ProteinFragment objects and returns target-overlapping prediction rows with source, sample and evidence metadata intact.

The bundled Sid regressions cover ATP5MG–KMT2A (a coding hypothesis with ambiguous donor annotation), GABBR1–SLC29A1 T1 (unresolved frame with direct junction support), and the latter’s unchanged raw alignment export. Their upstream sources and checksums are in tests/data/fusions/manifest.json.

Note on coordinate systems

varlens uses 0-based half-open coordinates internally. Many tools (including samtools and VCF files) use inclusive 1-based coordinates. We try to keep the confusion to a minimum by using the term “interbase” whenever we’re using 0-based half open coordinates and “inclusive” when we’re using 1-based inclusive coordinates.

One particularly sticky place this comes up is when specifying loci on the commandline using e.g. --locus chr22:43243-43244. To maintain consistency with the most common other tools, when you specify a locus like chr22:10-20, we interpret that as a 1-based inclusive coordinate. To specify 0-based half-open coordinates, use this syntax: chr22/11-20 (i.e. a slash instead of a colon).

See this blog post for more details on coordinate systems.

Python read-support API

varlens.support.variant_support(variants, counts) returns a pandas DataFrame with variants as its row index and two column levels named measurement and source. This replaces the removed pandas Panel API in Varlens 1.0:

evidence = variant_support(variants, counts)
alt_counts = evidence["num_alt"]  # one column per read source
tumor_depth = evidence[("total_depth", "tumor")]

The metrics are num_alt, num_ref, num_other, total_depth, alt_fraction, and any_alt_fraction. Commandline CSV columns retain their existing names. Counts include low-quality bases and overlapping mates unless read filters are requested. Common chr aliases resolve to BAM references; alternate and unplaced contig names are preserved.

MHC binding uses the current Topiary API with a local NetMHCpan installation. It reports the lowest affinity in nM among peptides overlapping the mutation, and the corresponding input allele. Variants without predictions have missing values. Prediction caches distinguish peptide-length requests. Effect labels come from the installed Varcode version and may change as its annotations improve.

Development

To run the tests from a git checkout:

pip install -e '.[test,fusion]'
pyensembl install --release 75 --species human
./lint.sh
./test.sh

External NetMHCpan tests are opt-in: run ./test.sh --run-netmhcpan with NetMHCpan and its model data installed. The other tests do not require it.

CI tests Python 3.11 through 3.14, both supported pandas major versions, and reference-dependent annotation in a separate job. A shared-stack job also installs Varlens, Vaxrank, MHCTools, and Trufflepig together with normal dependency resolution and runs pip check. To reproduce that check in a fresh environment:

python -m pip install -e '.[test,fusion]' -r requirements-openvax.txt
python -m pip check
./test.sh

Refresh editable metadata from the existing checkout with pip install -e . after changing its requirements. The metadata test checks every visible Varlens distribution against the source version, including stale editable metadata in site-packages.

In a shared environment, resolve all installed OpenVax consumers together and preserve existing editable checkouts. Trufflepig 1.28 requires pandas below 3, so pandas 2.3.3 is compatible with that release. Vaxrank 3.46.1 requires Oncoref 1.9.12, while Pirlygenes 6.0.14 requires Oncoref 1.8.210; Vaxrank 3.45.0 is compatible with the latter. Do not force these conflicting versions into one environment. Repository-local release environments are separate from the shared environment and can use pandas 3.

To build the documentation (just this README plus the commandline tool help):

pip install -e '.[docs]'
python -m sphinx -W --keep-going -b html docs docs/_build/html

The docs will be written to docs/_build/html. Maintainers with push access can publish them using ./deploy-gh-pages.sh; it builds in a temporary directory and updates the existing GitHub Pages branch without rewriting its history. Set PYTHON to select a particular environment’s Python executable.

usage:
